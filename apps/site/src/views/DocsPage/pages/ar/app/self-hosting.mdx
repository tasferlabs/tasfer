<h2 id="what">ما هو؟</h2>

يوجد المُرحِّل في [`apps/live`](https://github.com/tasferlabs/tasfer/tree/main/apps/live): وهو Cloudflare Worker مكتوب بـTypeScript، مع Durable Object لكل موضوع اكتشاف كي يلتقي نظراء الموضوع على النسخة نفسها. ويحمل [`apps/cli`](https://github.com/tasferlabs/tasfer/tree/main/apps/cli) الخدمةَ نفسها كعملية Node لمن لا يرغب في تشغيلها على منصة غيره. وفي الحالتين يوفر نقطة نهاية واحدة:

<h2 id="node">شغّله على آلتك</h2>

المُرحِّل المحمول هو الخدمة نفسها بلا Cloudflare: عملية Node واحدة، وغرف في
الذاكرة بدل Durable Objects، و[coturn](https://github.com/coturn/coturn) بدل
Cloudflare Calls. يتحدث البروتوكول ذاته، فيتصرف التطبيقُ المبنيُّ على عنوانه
كما يتصرف تمامًا مع المُرحِّل المستضاف.

```bash
cd apps/cli
npm install
npm run build

# Behind a TLS-terminating proxy, bind to localhost (the default):
node dist/main.mjs relay --port 8787

# With TURN, so peers behind strict NAT still get a direct path:
node dist/main.mjs relay --port 8787 \
  --turn-url turn:turn.example.org:3478 \
  --turn-secret "$(cat /etc/coturn/static-auth-secret)"
```

وإن ضبطت `TURN_KEY_ID` و`TURN_API_TOKEN` في البيئة بدلًا من ذلك، أصدرها عبر
Cloudflare Calls — المسار نفسه الذي يسلكه Worker — لمن يملك مفتاحًا بالفعل. وإن
لم يُضبط أي منهما، عمل الأقران بـSTUN فقط ومرّروا بياناتهم المشفّرة عبر هذه
العملية.

تجري ترقية WebSocket على `/topic/{topicHex}`، ويجيب `/health` بعدد الغرف
والأقران الحاليين ليفحصه مشرف العمليات. ويحتاج الوسيط العكسي إلى تمرير ترويسات
الترقية؛ وفي nginx هي `proxy_set_header Upgrade $http_upgrade;` و
`proxy_set_header Connection "upgrade";`.

<Callout kind="note" title="إنهاء TLS مسؤوليتك.">بخلاف Worker، تقدّم هذه العملية HTTP عاديًا. ضعها خلف Caddy أو nginx أو Traefik ليصل إليها التطبيق عبر `wss://`.</Callout>

<h2 id="run">شغّله على Cloudflare</h2>

يتطلب النشر حساب Cloudflare وأداة Wrangler:

```bash
cd apps/live
npm install

# TURN credentials for the NAT-traversal fallback (Cloudflare Calls):
npx wrangler secret put TURN_KEY_ID
npx wrangler secret put TURN_API_TOKEN

npx wrangler dev
npx wrangler deploy
```

اضبط نطاقك في `apps/live/wrangler.toml`، ثم ابنِ التطبيق باستخدام `VITE_SIGNAL_URL=wss://signaling.example.org`. راجع [استخدام مُرحِّلك](/docs/app/sync-relay#own-relay).

<h2 id="notes">ملاحظات تشغيلية</h2>

- **تتولى Cloudflare أمر TLS والتوسع.** يعمل Worker على شبكتها الطرفية، فلا شهادات تديرها ولا موازن حمل تضبطه.
- **يمرر نصًا مشفرًا معتمًا.** تُشفّر الإشارات وإطارات المسار البديل على الجهاز قبل وصولها إلى Worker؛ فلا مفتاح فك تشفير في الخادم يحتاج إلى حمايته، وهذا هو المقصود.
- **إصدار بيانات اعتماد TURN محكوم بحدود.** لا تُصدر بيانات الاعتماد إلا لأعضاء الغرفة المتصلين — لا عبر HTTP مجهول أبدًا — ويُخزن إصدار واحد مؤقتًا لكل غرفة، وتضع ميزانية يومية إجمالية سقفًا لفاتورة TURN على الحساب في أسوأ الأحوال.
- **نشرتان وبروتوكول واحد.** يعتمد Worker على Durable Objects وCloudflare Calls، بينما يحفظ مُرحِّل Node الغرف في ذاكرة العملية ويصدر بيانات اعتماد coturn. و`apps/live` هو التطبيق المرجعي للبروتوكول الذي يلتزم به الاثنان — ولا يستطيع أي عميل التفريق بينهما.
- **مُرحِّل Node عملية واحدة.** تعيش الغرف في ذاكرتها، فإن وزّعت الحمل على عدة نسخ وجب أن يصل أقران الموضوع الواحد إلى النسخة نفسها (بتوزيع قائم على المسار)، وإعادة التشغيل تُسقط كل الاتصالات. يعيد العملاء الاتصال من تلقاء أنفسهم، ولا يضيع لك شيء لأنه لم يُخزَّن لك شيء.
