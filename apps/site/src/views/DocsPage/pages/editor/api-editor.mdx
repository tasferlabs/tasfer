<Lede>
  `createEditor(options)` returns a `TasferEditor` — the view, the document
  mutator, and the selection owner over a CRDT document. It's the object you hold
  onto for the lifetime of the editing surface, and the only handle you need for
  single-player editing.
</Lede>

<h2 id="create">createEditor(options)</h2>

```ts
import { createEditor } from "@tasfer/editor";
const editor = createEditor(options: CreateEditorOptions): TasferEditor;
```

<Callout kind="note" title="A `Doc` does not need an editor.">`createDoc` takes no `element` and touches no DOM, so a document can live entirely on its own — on a server, in a worker, or in a test — and still be read with `doc.getMarkdown()`, synced with `applyUpdate`, and persisted with `encodeState()`. `createEditor` is the *view* layer over it; you only need one where there is something to render into.</Callout>

<h2 id="reading">Reading state</h2>

The editor never hands you a mutable store. `state` is a fresh, immutable snapshot rebuilt on every read; `getMarkdown()` projects the current document to text. The **`query` facet** is the read mirror of [`change`](/docs/editor/api-commands#targets): every method speaks the **same `DocPoint`/`DocRange` vocabulary the [ChangeApi](/docs/editor/api-commands#targets) accepts** and defaults to the live caret/selection. `block`/`blocks` mirror `change`'s point-vs-range split — `query.block(at)` pairs with `setBlock(attrs, at)`, and `query.blocks(range)` reads the span the selection covers. So you read a position and hand it straight back to a mutation without ever reaching into raw state. The selection itself (the caret/anchor `DocRange` with offsets) lives on the reactive snapshot at `state.selection.range`.

<Callout kind="note" title="state is a value, not a store.">`editor.state` is replaced — never mutated — on each transaction. Capture it in a variable only for the duration of one read; for live UI, recompute inside a `change` / `selectionchange` handler.<ForFramework fw="react"> In React, don't: `useEditorState` from `@tasfer/react` does that subscription for you.</ForFramework></Callout>

<h2 id="writing">Changing the document</h2>

You never mutate the document directly — you describe edits through the `ChangeApi`, and the editor applies them as CRDT operations. Every method here commits as one undoable step. These are summarised below and documented in full on [Changes & actions](/docs/editor/api-commands).

<PropsTable cols={["Method", "Signature", "Description"]} rows={[
  { name: "change", type: "(fn: (c: ChangeApi) => void) => boolean", desc: "Apply mutations as ONE undoable step. The callback's methods chain. Returns whether anything changed." },
  { name: "canChange", type: "(fn) => boolean", desc: "Dry-run a change: would those mutations change anything right now? (For enabling a toolbar button.)" },
  { name: "setMarkdown", type: "(md: string) => void", desc: "Replace the whole document with markdown. One undoable, broadcast transaction." },
  { name: "undo / redo", type: "() => boolean", desc: "Step local history. Remote edits never enter your undo stack." },
]} />

```ts
editor.change((c) => c.setMark("strong"));

// several edits, one undo step
editor.change((c) =>
  c.setBlock({ type: "heading", level: 1 }).insertText("Untitled"),
);
```

<h2 id="dispatch">Actions & hooks</h2>

Actions are named, dispatchable behaviours a host can observe or override — the seam for slash commands, link clicks, native gestures, and custom mutations. See [Changes & actions](/docs/editor/api-commands#actions) for the three action kinds.

<PropsTable cols={["Method", "Signature", "Description"]} rows={[
  { name: "dispatch", type: "(action, ...args) => boolean", desc: "Dispatch an action through this editor's bus. Returns whether a handler claimed it (or, for a mutation action, whether the document changed)." },
  { name: "registerAction", type: "(action, handler, priority?) => () => void", desc: "Observe or override an action. Higher priority runs first (default 0); return true to claim it. Returns an unsubscribe fn." },
]} />

```ts
import { OPEN_LINK } from "@tasfer/editor";

// Override a built-in action: open links through the host's own router
// instead of the engine's default. Returning true claims it (stops the
// default); return void to observe and let the default still run.
const off = editor.registerAction(OPEN_LINK, ({ url }) => {
  router.push(url);
  return true;
});

// later — detach the handler
off();
```

A handful of built-in actions are dispatched by the engine for hosts (and custom nodes) to observe or override:

<h2 id="keyboard">Keyboard</h2>

The editor consumes only the chords its keymap answers, and lets every other Ctrl/Cmd chord bubble to the host untouched — so an app-level listener for save, find, a command palette or a sidebar toggle works while the caret is in the canvas, with no editor configuration. "Cmd" below is ⌘ on Apple platforms and Ctrl elsewhere; chords are matched on the physical key (`KeyboardEvent.code`), so they survive a non-Latin layout.

<PropsTable cols={["Chord", "Action", "Notes"]} rows={[
  { name: "Cmd+Z / Cmd+Shift+Z / Cmd+Y", type: "undo / redo", desc: "Always claimed." },
  { name: "Cmd+A", type: "select all", desc: "Always claimed." },
  { name: "Cmd+B / Cmd+I / Cmd+E", type: "toggle strong / emphasis / code", desc: "Claimed only while the schema registers and allows that mark: a title field built with restrict({ marks: [] }) lets Cmd+B through to the host." },
  { name: "Cmd+Shift+X", type: "toggle strike", desc: "Same rule as the other marks. A plain Cmd+X is the native cut and is never claimed." },
  { name: "Cmd+Enter, Shift+F10, Menu", type: "context menu", desc: "Dispatches OPEN_CONTEXT_MENU (see above)." },
  { name: "Ctrl+A/E/B/F/P/N/H/D/K", type: "emacs caret moves", desc: "macOS only, bare Ctrl. Elsewhere these codes reach the host — Ctrl+F is its find." },
]} />

Copy, cut and paste are not intercepted at all: they reach the browser's native clipboard events, which is what the `copy`/`cut`/`paste` methods above also drive. A chord with Alt held is never claimed either — on Windows that is AltGr, which types a character. There is no built-in save chord: what saving means is the host's decision, so listen for Cmd+S yourself and read `getMarkdown()` or the `Doc`.

<h2 id="events">Events</h2>

`on(event, cb)` subscribes and returns an unsubscribe function. For state-driven UI outside React there is also `subscribe(listener)` — it delivers a fresh `EditorStateSnapshot` after every render-loop diff, rather than per named event, and likewise returns its own unsubscribe. (`useEditorState` is this wrapped for React.) The `change` listener receives a `ChangeTransaction` (`{ isRemote, ops }`); the others receive an `EditorStateSnapshot` — the same immutable value as `editor.state`.

<PropsTable cols={["Event", "Fires when", "Payload"]} rows={[
  { name: "change", type: "ChangeTransaction", desc: "The document changed — typing, paste, undo, or a remote sync. { isRemote, ops }." },
  { name: "selectionchange", type: "EditorStateSnapshot", desc: "The caret or selection moved, with no document edit." },
  { name: "focus / blur", type: "EditorStateSnapshot", desc: "The canvas gained or lost focus." },
]} />

```ts
const off = editor.on("change", (tx) => {
  if (tx.isRemote) return;            // ignore edits that came from a peer
  localStorage.setItem("draft", editor.getMarkdown());
});
// later
off();
```

<Callout kind="note" title="There is no `sync` event on the editor.">Connection status and peer count come from the *provider*, not the editor — the provider owns the transport. Subscribe with `provider.on("sync", …)`. See [Collaboration](/docs/editor/collaboration).</Callout>

<h2 id="lifecycle">Lifecycle</h2>

```ts
const editor = createEditor({ element });

// ... use it ...

// always destroy when the surface unmounts, or you'll leak the canvas
// layers, the ResizeObserver, the portal, and any providers attached to
// editor.doc. createEditor's destroy() does the *full* teardown.
editor.destroy();
```
