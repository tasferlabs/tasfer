<h2 id="crdt">The document is a CRDT</h2>

A CRDT (conflict-free replicated data type) is a way to store a document so that everyone can edit their own copy, and the copies always merge into the same result. No server has to decide who wins.

Two people can type in the same paragraph, both offline. When they reconnect, they both see the same text.

Want the long version? Watch Martin Kleppmann's [*CRDTs: The Hard Parts*](https://www.youtube.com/watch?v=PMVBuMK_pJY). It is one hour on why merging edits is harder than it looks, and it is the best explanation we know.

In `@tasfer/editor` this is not a feature you turn on. The CRDT is the document. Markdown is something you read out of it, not the place your data lives.

<Callout kind="note" title="No server needed.">The document does not know what a server is. Saving, syncing and showing who is online are optional providers you add on top. That is why the same editor works offline, peer-to-peer, or with your own backend.</Callout>

<h2 id="canvas">Why a canvas, not contenteditable</h2>

`contenteditable` is the browser's built-in way to make text editable. It is thirty years old, and every editor team ends up fighting it.

Tasfer draws the document on a canvas instead and does everything itself: layout, the caret, selection, right-to-left text, and typing with an IME. You get three things:

- **The same layout everywhere.** The editor decides where each line goes, not the browser. No surprises like Enter making a `<div>` in one browser and a `<p>` in another.
- **Full control of selection.** The caret, the highlight and other people's carets are shapes the editor draws itself. Selection follows the document's own rules, for example around right-to-left text and blocks that select as a whole.
- **Fast on long documents.** Only the lines on screen are drawn, so a long document scrolls like a short one.

The DOM is still there, just hidden:

- A hidden `contenteditable` sits behind the canvas. It takes the focus and receives the keyboard, IME and clipboard.
- A second hidden tree copies the document's structure (headings, lists, code, marks) for screen readers.

Neither one draws text. The browser never lays out what you type.
