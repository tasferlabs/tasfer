<Lede>
  The editor draws its own pixels, so you cannot style it with CSS selectors.
  You give it a plain `theme` object instead: **tokens** for colors, **styles**
  for sizes and spacing, and **fonts**.
</Lede>

<h2 id="tokens">The theme object</h2>

Pass `theme` to `createEditor`. Colors go under `tokens`. Every token is optional, so set only the ones you want to change.

```ts
import { createEditor } from "@tasfer/editor";

const editor = createEditor({
  element,
  theme: {
    // colors; anything you leave out keeps its default
    tokens: {
      text: "#1c1c1f",
      heading: "#09090b",
      cursor: "#1db984",
      selection: "rgba(29,185,132,0.30)",
      link: "#1db984",
      codeBackground: "#f4f4f5",
    },
    // which font to use, and the CSS font stack behind each name.
    // Loading the font files is your job.
    fontFamily: "serif",
    fonts: { families: { serif: '"Libre Baskerville", Georgia, serif' } },
  },
});
```

**Tokens or styles?** `tokens` are the colors: text, heading, cursor, selection, link, and so on. `styles` is for everything finer, like the font size of one block type, the padding, or the scrollbar. You can override any single value in it.

**One block, not all of them.** A theme styles every block of a type the same way. To style one block, give it its own `style` with `setBlock({ style: { … } })` (see [Changes & actions](/docs/editor/api-commands)). The block's own style wins over the theme, and the theme wins over the defaults.

Keys under `styles.blocks` are camelCase (`bulletList`, `numberedList`, `todoList`), while block type names use underscores (`bullet_list`).

`DEFAULT_TOKENS`, `resolveTheme` and `mergeTheme` are exported if you want to read or build a theme yourself.

<h2 id="live">Updating the theme live</h2>

`editor.setTheme(patch)` merges your patch into the current theme and repaints. Use it for a dark-mode toggle:

```ts
editor.setTheme({
  tokens: { text: "#e6e6e6", heading: "#ffffff", background: "#0b0b0c" },
});
```

<h2 id="css-vars">Driving it from CSS variables</h2>

The editor **never reads the DOM**, so it cannot pick up CSS variables by itself, and there is no `"inherit"` value. Read the variables yourself and pass them as `tokens`: once on mount, and again when your theme class changes.

```ts
function tokensFromCss(el: HTMLElement) {
  const v = getComputedStyle(el);
  return {
    text: v.getPropertyValue("--editor-text").trim(),
    cursor: v.getPropertyValue("--editor-cursor").trim(),
    selection: v.getPropertyValue("--editor-selection").trim(),
  };
}

const editor = createEditor({ element, theme: { tokens: tokensFromCss(element) } });

// dark mode flips a class on <html>, so read the variables again
new MutationObserver(() => editor.setTheme({ tokens: tokensFromCss(element) }))
  .observe(document.documentElement, { attributes: true, attributeFilter: ["class"] });
```

The Tasfer app themes its own editor the same way: it reads its CSS variables and passes them in as tokens.

<h2 id="metrics">Sizes and spacing</h2>

Sizes and spacing are not tokens. They live in `styles`, and you can override each one:

<PropsTable cols={["Path", "Default", "Description"]} rows={[
  { name: "styles.blocks.paragraph.fontSize", type: "16", desc: "Paragraph text size in px. Headings have their own: 30, 24 and 20." },
  { name: "styles.blocks.paragraph.lineHeight", type: "1.5", desc: "Line height as a multiple of the font size. Headings use 1.3." },
  { name: "styles.blocks.heading1.paddingTop", type: "32", desc: "Space above the block in px. 26 and 20 for heading 2 and 3, 0 for body text." },
  { name: "styles.blocks.code.marginTop / marginBottom", type: "8 / 16", desc: "Space around a block with a filled background. Quote and math have the same fields. Two such blocks in a row get no gap between them." },
  { name: "styles.canvas.paddingTop / paddingBottom", type: "4 / 80", desc: "Space above and below the document in px." },
  { name: "styles.canvas.paddingLeft / paddingRight", type: "40 / 40", desc: "Space left and right of the document in px. 16 on screens narrower than 768px, unless you set it. The text fills the rest of the container; there is no max-width setting." },
]} />

```ts
createEditor({
  element,
  theme: {
    styles: {
      blocks: { paragraph: { fontSize: 17 } },
      canvas: { paddingLeft: 64, paddingRight: 64 },
    },
  },
});
```

<h2 id="caret-selection">Caret, selection & placeholder</h2>

These live in `styles` too:

<PropsTable cols={["Path", "Default", "Description"]} rows={[

  { name: "styles.selection.cornerRadius", type: "0", desc: "Corner radius of the selection highlight in px. opacity (0.2) is how see-through the fill is." },
  { name: "styles.selection.remoteOpacity", type: "0.2", desc: "Fill opacity of another person's selection, when their decoration does not set one." },
  { name: "styles.remoteCursor.caretWidth", type: "2", desc: "Width of another person's caret in px. labelGap (2) is the gap between the caret and the name label." },
  { name: "styles.placeholder.showUnfocused", type: "false", desc: "When true, every empty block shows its placeholder, not only the one with the caret." },
]} />

The placeholder can look different per block type. Each block's style takes a `placeholder` with `color`, `fontScale` (a multiple of the block's font size) and `fontWeight`.

```ts
editor.setTheme({
  styles: {
    selection: { cornerRadius: 4 },
    blocks: {
      heading1: { placeholder: { color: "#b9b9c2" } },
      quote: { placeholder: { fontScale: 0.8 } }, // a smaller hint
    },
  },
});
```
