<h2 id="node">Define a node</h2>

A node is a block type. It declares its attributes (replicated CRDT fields), how it serializes, and how it draws. A callout box:

```ts
import { defineNode } from "@tasfer/editor";

const callout = defineNode("callout", {
  // Replicated attributes — each becomes a CRDT-settable field with a default.
  attrs: { tone: { default: "note" } },
  // Declarative paint for the built-in box renderer (or pass `node` for a
  // custom canvas Node). Round-trips through a generic <x-callout tone="…" />
  // tag, so no tokenizer changes are needed.
  render: {
    background: "rgba(29,185,132,0.10)",
    borderLeft: { width: 3, color: "#1db984" },
    label: (block) => `Callout (${block.tone})`,
  },
});
```

Prefer a class? Subclass a node and register the instance directly. The class owns its drawing, strings, and UI; a `static nodeConfig` supplies the same attrs/serialization `defineNode` takes. Both styles produce identical data, so they're interchangeable:

```ts
import { AtomicNode, baseSchema } from "@tasfer/editor";

class CalloutNode extends AtomicNode {
  readonly type = "callout";
  // Attrs + serialization, read when the class is registered directly.
  static nodeConfig = { attrs: { tone: { default: "note" } } };

  protected intrinsicHeight() {
    return 48;
  }
  protected draw(box, c) {
    c.ctx.fillStyle = "rgba(29,185,132,0.10)";
    c.ctx.fillRect(box.x, box.y, box.width, 48);
  }
}

const schema = baseSchema.extend({ nodes: [new CalloutNode()] });
```

<h3 id="nested-caret">A caret inside a node's own content</h3>

Most nodes hold their text in the block, and the editor's caret addresses it by index. A node whose content lives entirely in a [structured attachment](/docs/editor/api-schema#structured) — a table's cells, say — has no such index, so it owns both directions of the caret itself:

```ts
class GridNode extends Node {
  // point → address: where a click lands, as an identity-bearing ContentPoint.
  contentSelectionFromPoint(layout, local, c, options) { … }

  // address → point: the rect to draw the caret at. Without this a nested
  // caret is simply never painted, because core's caret geometry ends at
  // TextNode.caretRect, which takes a flat text index.
  contentCaretRect(layout, point, c) {
    return { x: c.origin.x + …, y: c.origin.y + …, height: … };
  }
}
```

`c.origin` is the block's top-left in whichever space the caller works in (viewport when painting, document when scrolling the caret into view), so return the rect relative to it and both callers get what they need. Returning `null` — or leaving `contentCaretRect` unset, as every built-in node does — keeps the ordinary text-caret path.

Implementing the hook is also what makes the engine _paint_ a caret in a block that has no flat text of its own. Both cursor paths otherwise stop at blocks the schema marks as textual; a node that declares `contentCaretRect` is admitted past that gate, and `editor.view.coordsAtContent(point)` starts returning coordinates for the same point instead of `null`. Core never names the block type — the node's own hook is the credential.

Collaborators come through the same gate. A remote peer's caret inside your content arrives as a [caret decoration](/docs/editor/collaboration#presence) carrying a `ContentPoint`, and core places it with `contentCaretRect` exactly as it places the local one — you write nothing extra for it. Their _selection_ is a **range** decoration, and range decorations are painted by the node that owns the geometry: in `paint`, walk `decorationsForBlock(state.ui.decorations, block.id)` and hand the rects your local selection already uses to `paintDecorationRects(ctx, rects, deco, styles)`. That one call renders whatever style the decoration carries — the translucent fill a peer's selection uses, or the solid/wavy/dotted/dashed underline another producer asks for (see [Decorations](/docs/editor/api-editor#decorations)) — so your node never branches on the style itself. Give each rect a `baseline` (the absolute y of the text it covers) so an underline hangs where prose puts it; for a box with no text of its own, build the rect with `boxDecorationRect(box, deco)` and the underline hugs its bottom edge. Skip all this and a peer's caret shows in your node while their highlight is the one thing missing from it.

The rect is drawn verbatim, so the node owns how tall its caret looks. Return **text height** — ascent + descent — anchored at the top of the line, which is how prose measures its own caret. A line box is taller than that (it also carries the row's leading), so returning the full line height draws a caret noticeably taller than the one in the paragraph beside it.

To draw the text itself, use `paintTextRun`: it is the engine's own marked-line renderer, so a node that lays out its own line boxes still resolves marks, batches for Arabic ligatures and paints replacement runs identically to prose.

```ts
import { paintTextRun } from "@tasfer/editor";

paintTextRun({
  ctx,
  chars, // the field's document-order characters
  formats, // its mark ranges
  startIndex,
  endIndex, // the visible range of this line
  x, // the run's start edge — its RIGHT edge in RTL text
  baselineY,
  textStyle,
  fontFamily,
  styles,
  marks,
  isRTL,
  requestRedraw,
});
```

<h3 id="document-edge">Leaving a node at the document's edge</h3>

A block that stores no flat text has no caret position to offer at its own top or bottom edge. So when one sits first or last in the document, the editor grows an empty paragraph there rather than trapping the caret: clicking or tapping the blank page above or below it starts that paragraph and puts the caret in it, and so do ArrowUp/ArrowDown and PageUp/PageDown. A document whose only block is your node is never a document with nowhere to type.

Custom nodes get this without opting in — the engine asks whether the block type stores text, and a type it has never seen does not. Registered text blocks opt in per type instead, since the end of a paragraph is a perfectly good place for a caret.

The one thing to implement yourself is the keyboard half of a node with a **nested caret**. Claiming the vertical moves (as the [nested-caret hooks](#nested-caret) above describe) means claiming them at your node's edges too: while a nested selection is live the engine stands aside, because only your node knows whether the caret is on its last row or merely somewhere in the middle. When your own walk runs out of content, hand the caret on:

```ts
import {
  appendTrailingParagraph,
  prependLeadingParagraph,
} from "@tasfer/editor";

// No block after this one: grow the paragraph to land in. Both helpers clamp
// to the schema's `content` expression and return `{ kind: "fallthrough" }`
// when it forbids a block there — leave the caret put in that case.
const edge = appendTrailingParagraph(state, block);
if (edge.kind === "break") return { state: edge.state, ops: edge.ops };
```

<h2 id="strings">Localized strings live on the node</h2>

A node owns the canvas strings it paints — status labels, prompts — as a `strings` catalog of English defaults. The editor ships no i18n library; a localized host overrides per type via `theme.nodeStrings`. Read them inside `draw` with the protected `str(state, key)` helper. (The core image node and the opt-in math node own their labels exactly this way — they're no longer in a global string table.)

```ts
class CalloutNode extends AtomicNode {
  readonly type = "callout";
  readonly strings = { hint: "Add a note…" };

  protected draw(box, c) {
    c.ctx.fillText(this.str(c.state, "hint"), box.x + 12, box.y + 24);
  }
}

// Host overrides, keyed by block type then the node's local string key:
createEditor({
  element,
  schema,
  theme: { nodeStrings: { callout: { hint: "ملاحظة…" } } },
});
```

<h2 id="overlays">Node-owned UI (overlay slots)</h2>

A node can ask the host to float real UI — a popover, an inline editor — over one of its blocks, without the engine ever importing your UI framework. `overlays()` returns renderer-agnostic _descriptors_ (identity + geometry, derived from the block's data and the current UI state); the host maps each `key` to a component and mounts it at the descriptor's `rect`.

```ts
class CalloutNode extends AtomicNode {
  readonly type = "callout";
  overlays(c) {
    // Show an editor overlay while this block holds the caret.
    if (c.state.document.cursor?.position.blockIndex !== c.blockIndex)
      return [];
    return [
      {
        // Overlays are addressed by stable block id — the host component may
        // act on it after remote edits have shifted every index.
        key: "callout-editor",
        blockId: c.block.id,
        rect: { x: c.origin.x, y: c.origin.y, width: c.maxWidth, height: 48 },
      },
    ];
  }
}
```

The host drives them through one registry — no per-type `if` ladder. Recompute each frame and mount the registered keys at their rect:

```tsx
const OVERLAYS = { "callout-editor": CalloutEditor };

editor.host.collectOverlays().forEach((o) => {
  const Comp = OVERLAYS[o.key];
  if (Comp) mountAt(o.rect, <Comp overlay={o} editor={editor} />);
});
```

<Callout kind="note" title="The engine stays headless.">
  `overlays()` returns data, never JSX — so the same node works in a React host,
  a vanilla-DOM host, or none at all. It's the seam the core image and opt-in
  math popovers are migrating onto.
</Callout>

<h2 id="mark">Define a mark</h2>

A mark is inline formatting. The bare call registers a valid, replicated format name; pass `render` to paint it on the canvas (a `Mark` subclass) and `codec` to give it markdown delimiters and an HTML tag. Omit `render` and it survives via the CRDT but paints as plain text; omit `codec` and it's dropped on markdown export.

```ts
import { defineMark } from "@tasfer/editor";

// minimal — replicates, but paints as plain text and doesn't serialize
const highlight = defineMark("highlight");

// full — on-canvas paint + a `==text==` round-trip
const marked = defineMark("highlight", {
  render: new HighlightMark(), // a Mark subclass; style() returns the paint
  codec: highlightCodec, // delimiters + HTML tag
});
```

A `Mark` subclass can also declare `selectionWrap` — the typed delimiters that apply it over a held selection, VS Code-style auto-surround with markdown meaning. Typing a trigger char while text is selected applies the mark instead of replacing the selection (the core marks declare `` ` `` → code and `~` → strike; the optional math extension declares `$` → inline math). Marks sharing a char at different `level`s cycle with the delimiter count on repeated presses, the way emphasis (`*`, level 1) and strong (`*`, level 2) walk _em_ → **strong** → **_both_** → plain:

```ts
class HighlightMark extends Mark {
  readonly type = "highlight";
  // `=` typed over a selection toggles the highlight (think `==text==`).
  readonly selectionWrap = [{ char: "=" }];
  style() {
    return { background: { color: "#fde68a", padding: 2, borderRadius: 3 } };
  }
}
```

<h2 id="register">Register them</h2>

`extend` returns a _new_ immutable schema — the base is never mutated, so two editors on one page can run different schemas.

```ts
import { createEditor, baseSchema } from "@tasfer/editor";

const schema = baseSchema.extend({
  nodes: [callout],
  marks: [highlight],
});

const editor = createEditor({ element, schema });

// The doc carries the data half of the schema, so persistence and markdown
// round-trip the custom block losslessly:
editor.getMarkdown(); // …  <x-callout tone="warn" />  …

// The inferred schema type also reaches every editor operation:
editor.change((c) => {
  c.insertBlock({ type: "callout", tone: "note" });
  c.setBlock({ type: "callout", tone: "warning" });
  // c.setBlock({ type: "calluot" }); // TypeScript error
});

const block = editor.query.block();
if (block?.type === "callout") {
  block.attrs.tone; // inferred from defineNode
}
```

A spec carries every facet its type owns — there is no separate facet registry.
Both `defineNode` and `defineMark` accept `markdownSyntax`, the Markdown
recognizers for the type's own syntax, and `defineMark` also accepts
`structured` for structured-content behavior (eager attachment
initialization, canonical-source resolution from the attachment, attachment
references, clone rewrites). A structured mark stores no source text in block
characters: it anchors on a single placeholder character and its attachment is
the only content authority. A custom syntax rule only takes
effect when a codec claims the tokens it emits; the generic `<x-type/>`
round-trip claims none, so pair the rule with a hand-written codec — the way
the optional math specs carry the `$$…$$` and `$…$` recognizers next to the
codecs that read them.

<Callout kind="tip" title="Schema changes are CRDT-safe.">
  Blocks are addressed by type *name* in the replicated log, so a peer running
  the same schema merges your callouts cleanly. A peer that *doesn't* have the
  type doesn't crash or lose data — it keeps the ops and renders an "unsupported
  block" placeholder until it's upgraded. Ship schema changes to all peers
  together, the way you'd ship a database migration.
</Callout>

To constrain which of these registered types a given editor may _author_ — a
one-line title, a comment box — narrow the schema with
[`restrict`](/docs/editor/api-schema#restrict). It gates creation only: a
restricted editor still _renders_ a `callout` that a collaborator (or a paste)
brings in, because the type stays registered.
